`examples/gui/` is a graphical client for Cante built with
[PocketJS](https://pocketjs.dev) — a portable runtime that compiles Solid
components into a native UI tree (no browser engine, no runtime CSS). The same
source renders as a desktop window and as a 480×272 handheld screen.

It follows the shape of Codex and Claude Desktop: a session rail on the left, a
streaming transcript in the middle, a composer pinned to the bottom, and a
token / context strip under it. Tool calls render as cards, and approval
requests open a panel where each call gets its own decision.

## Why a bridge is involved

PocketJS gives a guest a **bounded, whole-response HTTP client** — `fetch` with
a 256 KiB response ceiling, no sockets, no streaming, no WebSocket. Cante's
daemon speaks `Op`/`Evt` JSON Lines over stdio, a Unix socket, or a WebSocket.
So the example ships both halves:

```
cante (stdio JSONL)  ⇄  bridge (Bun, loopback HTTP)  ⇄  GUI (PocketJS fetch)
```

`examples/gui/bridge/cante-bridge.ts` spawns `cante serve`, forwards
operations, keeps a bounded ring of events, and answers
`GET /events?cursor=N` with a cursor-addressed long-poll. Batches coalesce
delta runs and are capped by count and bytes, so one response always fits the
guest's ceiling.

The bridge is a transport only: it adds no policy, and it never fabricates
protocol events. Everything the GUI shows comes from Cante.

## Running it

```sh
# 1. the bridge (loopback only; it starts `cante serve` on the first session)
bun examples/gui/bridge/cante-bridge.ts

# 2. the app — see examples/gui/README.md for the PocketJS checkout setup
cd examples/gui && ./scripts/pocket.sh dev
```

The bridge listens on `http://127.0.0.1:4317` and uses `cante` from `PATH`;
override with `CANTE_GUI_PORT` and `CANTE_BIN`. If the bridge or the daemon
goes away, the GUI shows a *bridge offline* bar and reconnects on its own.

## What it drives

| Control | Operation |
| --- | --- |
| Composer | `UserInput` (and `Steer` / `ShellInput` modes) |
| Approval panel | `ApprovalResponse` with a per-call `Once` / `Session` / `Always` / `Deny` |
| Stop (`SQUARE`) | `Interrupt` |
| Model & provider picker | `StartSession` with the picked provider/model |
| Effort & permissions rows | `UpdateSession` — applies next turn, keeps the conversation |
| Compact / Context report | `Compact` / `ContextReport` |

Model and provider lists come from `cante catalog` through the bridge, so the
picker shows the same providers and model ids as the CLI.

## Building the app

PocketJS builds inside a PocketJS checkout, so the example carries a script
that materializes one and symlinks the app into it:

```sh
cd examples/gui
./scripts/pocket.sh check                     # manifest + capabilities + typecheck
POCKET_TARGET=psp ./scripts/pocket.sh check   # validate another target profile
```

See [`examples/gui/README.md`](https://github.com/muyouming/cante/blob/main/examples/gui/README.md)
for the manifest, the bridge API table, controls, and current limitations.
