## 4. 反向验证

### 4.1 把随包的 `pi\` 挪走 → 向导**没有**如实说缺 ✗✗（本报告最重要的一条）

做法：`Move-Item %LOCALAPPDATA%\Cante\pi → %TEMP%\acc7\pi-moved-away`（挪走，不是删；
`Test-Path` 确认应用旁边已经没有 `pi`），清掉 WebView2 档案，零环境变量启动应用，点「开始检查」。

**向导原文**（`reverse-missing-pi.txt`）：

```
检查你的电脑
已经就绪
电脑这边都准备好了，可以开始干活。
[下一步]
```

**它应该说**（清单 §6：向导必须如实说缺并给出她能做的一步）：`这台电脑上缺一个动手的组件…`
+ 一个具体下一步 —— 也就是**没有**。

**根因**（读代码定位，不是猜）：`gui/src/simple/Wizard.tsx` 的绿勾是

```ts
const ready = (): boolean =>
  !bridgeMissing() && !failed() && health()?.ok === true && !!health()?.cante;
```

`health` 是 Rust 那条启动 `<安装目录>\cante-bridge.exe --version` 的探测 —— **桥能跑它就返回版本号**，
于是"桥在、执行组件不在"照样算就绪 ✗。我第二步在 `commands.rs::resolve_daemon_bin` 里加的
"找到随包发的桥之后还要看执行组件在不在"（`gui/executor` 那条），只喂给 `daemon_capability`，
**没有参与这个绿勾** ✗。

**她最终会看到的那句话是对的，只是太晚**：把 `pi\` 挪走之后，直接驱动**包里的桥**（零环境变量）
拿到的是（原文）：

```
[event] {"event":{"Error":"这台电脑上缺一个动手的组件，重新安装一次 Cante 就能补上。"} …}
[pi stderr] cante-bridge: 没找到动手的组件；找过：["C:\Users\<用户名>\AppData\Local\Cante\pi",
            "C:\Users\<用户名>\.cante\bin\pi", "系统里登记的每个文件夹"]
```

也就是说：**不会静默失败、不会崩** ✓，但**她会先看到绿勾、点一张卡、点「开始」，才发现"缺一个动手
的组件"** ✗ —— 违反"动手前就说清"的那条产品律。

**修法方向（下一轮，属于代码改动；这一轮任务明确要求只加报告文件，所以没动 ✗）**：
让 `ready()` 把 `daemon()`（`daemon_capability`）也算进去 —— 当解析出来的桥是**我们随包发的那一个**
时，要求 `daemon()?.available` 为真；并给这条加一条界面测试（现在没有 ✗）。

  下载文件**触发；这台机器又是 SSH 会话、**没有交互桌面**，弹窗即使出现我也看不到。安装包与两个
  exe 都是 **NotSigned** ✓（这是触发它的前提之一）。
- **真实的杀毒拦截** ✗：这一轮实时保护开着、全程零拦截，但"真被拦下时界面上是什么样"我只用
  **假的 `bun.exe`** 模拟到了桥那一层的中文原文（§4.2），没有真的让 Defender 去拦一次。
- **防火墙** ✗：三个配置文件都关着，无从验证（§5）。
- **向导在"执行组件缺失"时的表现** ✗：实测是**错的**（§4.1）—— 这条不是"没验"，是"验了、不合格"。
- **干净机器 ≠ 这台机器**：这一轮是"先卸载、清掉 `%APPDATA%\Cante` 与 `~\.cante`、清掉 WebView2 档案"，
  不是全新安装的 Windows 或新用户；`%LOCALAPPDATA%\dev.cante.gui` 那一步卸载后**按预期保留** ✓。
- **画面**：SSH 会话没有交互桌面，我拿到的是 WebView2 的 DOM 文字（UI Automation）与驱动截的
  `result.png`（渲染结果），**不是**肉眼看窗口；"窗口真的画在屏幕上"这件事这轮没验 ✗。
