## 第 4 批真机挖出来的（**只有真机能发现** ✓，优先做 ✓）

### P0 · 结果面板 **47 行的按钮名字全一样** ✗（读屏分不清是哪一份）

**判据**：`gui/WINDOWS-ACCEPTANCE-19.md` §3.1 ✓（**真 WebView2 + 真 UIA** ✓）：
> 结果面板 **92 个可 Tab 按钮只有 4 个不同名字** ✗，**47 行按钮名字全一样** ✓，
> **读屏分不清是哪一份结果** ✗。

**连带问题**（同一份报告 §2 原话 ✓）：因为名字都一样 ✓，那个 UIA 走查脚本**按名字去重**，
**把"不同行"误判成"卡住了"** ✗ —— 也就是说 **这个缺陷会骗测试** ✓。

**现状（我核过 ✓）**：`ResultsPanel.tsx` 里每行的按钮用
`aria-label={RESULTS.actions.ariaOpen}` ✓ —— **一个常量** ✗（`copy-results.ts:70` ✓「打开这个结果文件」✓）。

**做法**：名字带上下文 ✓（文件名 / 来自哪张卡 / 做好的时间 ✓ —— 都在 `entry` 里 ✓），
例如「**打开 结果_挑出_华东区.xlsx**」✓；**不许**塞机器路径 ✗，**不许**改成"结果 1 / 结果 2"✗
（她认不出来 ✓）；同一行两个按钮也要区分 ✓；判据做成**常驻闸门** ✓。
**不覆盖** ✗：真机 UIA 复跑（本机跑不了 ✓ —— 要等下一次真机 ✓）。

### P1 · 「她的环境比我们想的乱」✗ 一次都没验过

**判据**：她用的是**公司的电脑** ✓（分辨率 ✓、多屏 ✓、系统字体放大 ✓、主题 ✓ 都可能与我们不同 ✓）。
我们只在**一种**配置上验过：`1280x800` / 单屏 / 100% 缩放 / 一种主题 ✓。

**做法**：在真 Windows 上逐条试 ✓ —— 向导在 1280×800 下走一遍 ✓、多屏（有就试 ✓）、
**系统字体放大** 125%/150%（与显示缩放不是一回事 ✓）、切成另一种主题看对比度 ✓；
**改不了就如实写改不了 + 原因** ✓。

### P1 · 她点「停下」之后，屏幕上说不说清 ✗

**判据**：她**没有能力判断"停干净了没有"** ✗。产品律最该回答的三件：**已经做了一半的东西在哪** ✓、
**原文件有没有被动过** ✓、**还能不能接着来** ✓。

**现状（我 grep 过 ✓）**：`copy-recovery.ts` 有**停滞**那套 ✓（`STALLED_MARKER` ✓），
但**没有**一个「**刚刚点了停下**」的专属说法 ✗。

**做法**：**只加没跑偏的** ✓（三句以内 ✓）：一半的产出在不在（用已有的 `verify.ts` / `runs()` ✓）✓、
"**原来的文件没有被改动**"✓（我们能保证 ✓ —— 快照在 Rust 侧 ✓）、
一个 44px 的下一步按钮 —— **但先核对产品支不支持"接着做"** ✓，不支持就**别摆** ✗
（摆一个点了没用的按钮比不摆更坏 ✓）。

### P1 · 卡片上那些**她根本不认识的词** ✗

**判据**：可读性闸门量的是**句子结构** ✓；但有些词**她根本不认识** ✗，结构再短也没用 ✓。
反复出现的至少这几类：**「台账」**（卡名里就有 ✓）✓、**「对账」** ✓、**「汇总/分组/透视」** ✓、
**「去重」** ✓、**「列名/表头」** ✓、**「另存/导出」** ✓。

**做法**：一个可复用的**答案位** ✓（词旁边一个 44px 入口 ✓，点一下给**一句话** ✓
「**这在你这儿，就是把两张表里的钱数对一下**」✓）；**只做最确定的 3–5 个** ✓；
**不许**做成"术语词典"✗（她不会去查 ✓ —— 必须就在那个词旁边 ✓）。
**不覆盖** ✗：**她到底认不认识这些词**（这台机器答不了 ✓，要真人 ✓）。
