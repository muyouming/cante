# 她念不出那条位置（r15）：先核事实，再给她「复制位置」

这份文档回答 `AGENTS.md` §3.6 那个问题：**我要改的，是产品真的产出/真的执行的那个东西吗？**
先核四条事实（第一节），再说改了什么、什么没验到（后面几节）。

一手证据：`gui/docs/WINDOWS-REVEAL-PROBE.md`（真机，Windows 11 家庭版 build 10.0.26200）。
**读它时要注意一件事**：那份探针的**第 3 步**引用的界面原文是 `位置：C:/Users/<用户名>/…`，
而这行界面字**在它成文之前就已经改掉了**（见 A5）。所以那份探针的第 3 步在**这两条**上过期了，
它自己的核对结论（COM 不拼命令行、文件名/文件夹能打开）仍然成立。

## A. 四条事实（先核，再改）

### A1 `fileName` / `folderName` 在哪定义、被哪些界面用

定义：`gui/src/simple/run.ts:141`（`fileName`）/ `run.ts:146`（`folderName`）。两者都同时
认 `/` 与 `\` 两种分隔符（Windows 来的位置也用同一套）。

**真正用到它们的生产代码，逐个列**（去掉测试）：

| 模块 | 用哪个 | 用在哪 |
| --- | --- | --- |
| `ResultCard.tsx` | `fileName` | 结果卡片每一份文件的标题（`:578-579`）、「复制成微信」的摘要（`:289`） |
| `ResultsPanel.tsx` | 经 `results.ts` 转手 | 面板每一行的名字（`results.ts:101` 取 `fileName`） |
| `History.tsx` | `fileName` | 历史里文件名那一行（`:153`、`:167`） |
| `ConfirmSheet.tsx` | `fileName` + `folderName` | 确认页文件列表（`:392-394`、`:427-429`、`:521-522`） |
| `results.ts` | `fileName` + `folderName` | 结果面板的数据（`:101-102`） |
| `handoff.ts` | `fileName` | r11「把这个文件发给别人」的文件名（`:55`） |
| `evidence.ts` | `fileName` | 「上次也做成过」那句的文件名（`:91`） |
| `history-search.ts` | `fileName` | 历史搜索按文件名匹配（`:74-75`） |
| `approval.ts` | `fileName` | 审批卡里列出的文件（`:58`、`:63`） |
| `location.ts` | `folderName` | 把文件夹名翻成她认得的位置（`:54`） |

**结论**：`fileName`/`folderName` 是**拆名字**的纯函数，各自都能吃两种分隔符，本身不产生
正斜杠——正斜杠是它们的**输入**带进来的（见 A2）。

### A2 正斜杠是从哪来的、是不是有意为之

来源：`gui/src-tauri/src/files.rs:415-417`

```rust
/// A path as the rest of the product spells it: `/` separated.
/// … normalising costs nothing and buys one canonical spelling for
/// every consumer — the confirmation list, the prompt we hand the
/// assistant, the run log, and the before/after diff keys. …
fn display(path: &Path) -> String {
    path.to_string_lossy().replace('\\', "/")
}
```

**是有意为之**，不是顺手：注释写明它要的是**一种规范写法**，给**五个消费者**共用——
确认页、给助手的指令、运行记录、前后对比的键，以及（由此派生出的）所有显示位置的地方。
`display()` 的 6 处调用（`files.rs:239`、`:566`、`:623`、`:694`、`:725`）全都喂给这些消费端。

**影响面（改它的代价）**：这是 `files.rs` 里的函数，而本轮**不许碰 `files.rs`**；而且它同时喂给
给助手的指令与 diff 键——把显示改成反斜杠，就会**同时**改掉助手看到的指令与快照对比的键，
风险远大于收益。git 历史：`display()` 与这段注释是同一个提交（`8fb1300`，2026-09-16，
「the simple surface is the product」），没有后来"顺手改"的痕迹。

**所以本轮的处理是分开**：**显示不动**（仍是正斜杠），只在**要复制的那一份**换成反斜杠
（`copy-results.ts` 的新纯函数 `pathForClipboard`，见第二节）。`run.ts` 一行没改。

### A3 她能不能把这条位置粘进系统的「打开文件」对话框

**未核，需真机。** 本机没有 Windows，我**不猜**。

- **已核到的**（不是猜，是查来的）：Windows 的 API **普遍同时接受两种分隔符**——`display()`
  自己的注释就这么写（`files.rs:410-411`：「Windows APIs accept both separators」），
  探针第 2 步也实测过正斜杠路径的 reveal 能开。
- **没核到的**：Windows **「打开文件 / 另存为」对话框那个地址栏/文件名框**对正斜杠的容忍度。
  这属于**系统对话框自己的行为**，不是我们的 API 调用，探针没测过这一条（它测的是
  `SHOpenFolderAndSelectItems` / `ShellExecuteExW`，不是对话框）。**需真机粘贴一次才算数。**
- **所以这一轮的做法是"两头都给她"**：显示保持不变，复制出去的是**反斜杠**（Windows 习惯，
  她粘进对话框与微信都最像"一条正常的 Windows 位置"）。就算对话框其实也吃正斜杠，反斜杠
  也不会更差——它是 Windows 自己的写法。

### A4 界面里哪些地方已经有「复制」按钮（找现成模式，不自创新交互）

全仓库的复制动作（`navigator.clipboard` / `execCommand`）都在三处，用的是**同一套退路**：

| 位置 | 什么按钮 | 退路实现 |
| --- | --- | --- |
| `ResultCard.tsx:81` `copyText()` | 「复制成微信能贴的文字」、结果核对里的「复制详情」 | 先系统剪贴板，不让用就退到选中复制 |
| `ResultsPanel.tsx:71` `copyText()` | 「一次复制成微信能贴的文字」 | 同上（和结果卡片那份逐字同源） |
| `ErrorView.tsx:57` / `daemon.ts:125` | 出错页与「缺组件」页的「复制详情给同事」 | 同上 |

**现成模式**：一个 `copyText(text)` 本地函数 + 一条**一直挂着的提醒**「复制不是发送」+ 复制后
一句 `role="status"` 的结果话。本轮**复用这个模式**（复用 `ResultCard.tsx` 已有的那个
`copyText`，不新造交互），按钮样式也复用旁边「打开所在文件夹」那一套边框按钮。

## B. 改了什么（最小、且她能懂）

### B1 给她一步能做完的动作：`复制位置`（`ResultCard.tsx`）

- 按钮放在「打开文件 / 打开所在文件夹」**旁边**（同一个 `flex` 容器），样式复用旁边那个
  边框按钮（`min-h-[48px] rounded-xl border border-slate-600 …`），不新造交互；
- 按下去走**已有的** `copyText()`：整条位置进她的剪贴板。**复制不是发送**——只放到剪贴板，
  发不发、发给谁，她自己定（和「复制成微信能贴的文字」同一条红线）；
- 复制后给一句 `role="status"` 的结果话（成功 / 没成功），读屏也念得出；
- 按钮名字带文件名（`复制 <文件名> 的位置`），和旁边两个按钮同一条道理：一屏几十行时，
  读屏 Tab 到某一行的按钮要能听出是**哪一份**（`WINDOWS-ACCEPTANCE-19.md §3`）。

### B2 复制出去的是**反斜杠**，显示**仍是正斜杠**（分开处理，`copy-results.ts`）

新纯函数 `pathForClipboard(path)`：

- 认得出是 Windows 的位置（盘符开头，例如 `C:/…`）→ 分隔符全部换成 `\`，并合并连续分隔符；
- 别的位置（苹果 / Linux 那种以 `/` 开头的）**原样返回**——它们本来就用正斜杠，改了才是错的；
- 空串、认不出的，原样返回，**绝不猜**。

**为什么分开**：见 A2——`display()` 的正斜杠是**五个消费者共用**的规范写法，改它牵动
给助手的指令与 diff 键；而复制这个动作的**唯一目的**是"粘到 Windows 的地盘"（微信、对话框），
那里反斜杠才对。两个目的不同，就不该被同一根分隔符绑住。

### B3 显示这一轮**没有**改（为什么）

探针说的 `truncate` 截断位置那一行，HEAD 上**已经不存在**（A5）——位置那一行现在是一句
友好话，不会截断。所以本轮**不去撑开布局**（`AGENTS.md` 的告诫：长路径硬撑会挤坏卡片）。
`ResultCard.tsx:578` 文件名那行的 `truncate` 与 `title` 照旧，一个字没动。

## C. 断言（`gui/src/simple/path-for-her.test.ts`，16 条）

用 `results-names.test.ts` 同一套 **Solid SSR** 真渲染结果卡片（不是源码扫描），再加纯函数直测：

| 断言 | 挡什么 |

`fileName(file.path)` → 接线那条红 ✓；把复制按钮的 `aria-label` 换掉 → 按钮那 2 条红 ✓。

## D. 没验的（如实写）

   本机没有 Windows；探针也没测过系统对话框（它测的是我们调的两个 API）。**别把"能打开"
   当成"粘得进对话框"**——那是两件事。
2. **真机粘贴本身**（复制出来那串粘到微信 / 对话框里是否真能用）：**本机没 Windows，未验**。
   代码里验的只是"复制进去的是完整位置、且是反斜杠写法"；她那只手粘出来是什么样，
   要验收机另跑。
3. **`e2e.sh` 第 9 步 `dom-smoke.sh`**：本机跑过（见下"测试结果"），但它**不覆盖**真 WebView2、
   也不覆盖显示缩放（见 `gui/VERIFICATION-MAP.md` 那一行）。
4. **本轮的按钮不在「我做的结果」面板里**：面板的每一行也有一串位置，本轮**没动**
   （范围只到结果卡片）。面板那面要不要也加「复制位置」，留给下一轮判断——这里只说明
