## 5. 那个 GBK 报错：逐字节取回来了

**命令**（真机，`cante-sheets.exe` 来自装机目录）：

```
cante-sheets write <结果.xlsx> <GBK 的 CSV>      →  exit=2
stderr：读不了这个文件：C:\Users\<用户名>\AppData\Local\Temp\b15\gbk.csv（stream did not contain valid UTF-8）
```

**stderr 的原始字节**（UTF-8 编码，不是 936）：

```
e8 af bb e4 b8 8d ... （读不了这个文件：）
...
73 74 72 65 61 6d 20 64 69 64 20 6e 6f 74 20 63 6f 6e 74 61 69 6e 20 76 61 6c 69 64 20 55 54 46 2d 38
= "stream did not contain valid UTF-8"        ← 真英文
```

**判断**：括号里那句是 **Rust 标准库自己的错误原文**（`std::io::Error`，来自
`library/std/src/io/mod.rs`，在 exe 里也能直接找到这串字节，偏移 4111121）。
中文部分是 `bin/cante-sheets.rs:68` 拼的：
`.map_err(|error| format!("读不了这个文件：{input}（{error}）"))`。

→ **缺口成立** ✓：拒收 GBK 本身**是对的**（不猜编码、不乱码入库），
但**漏了英文、且缺一句"怎么办"** —— 违反产品律 3（出错能看懂并有出路）。
