# 可读性闸门：她读一句就能知道该做什么

这份文档解释 `gui/src/simple/readability.test.ts` 为什么这么判、数是怎么定的。
**测试是判据，这份文档是理由**——有人要调阈值或加白名单时，先读这里。

## 1. 它补的是哪一块空白

王姐看不懂一句中文，常常不是因为它含某个技术词：

| 已有闸门 | 挡什么 |
| --- | --- |
| `copy-guard.test.ts` | 黑名单**词**（模型 / token / 路径 / 会话 …） |
| `tone.test.ts` | **语气**（卖萌 / 夸张 / 空口保证 / 免责声明） |
| `typography.test.ts` | **字号**（正文 ≥16px、标题 ≥20px、按钮 ≥44px） |
| **`readability.test.ts`（本闸门）** | **句子本身难读**：太长 / 断句太多 / 没动作 / 名词堆叠 / 公文体 / 指代不明 / 被动句 |

一句话套三层从句、被动加抽象名词、代词指代不清——这些都不会命中黑名单，但一样会
让她卡住。本闸门把它们变成**机器能数的数**。

## 2. 七条规则，以及为什么是这个阈值

| 规则 | 判据 | 为什么是这个数 |
| --- | --- | --- |
| `long` 太长 | 一句 > **40 字** | 一条微信大约 30–40 字；再长，屏幕上要换行，她会漏掉后半句 |
| `pauses` 断句太多 | 一句里 `，、；：` ≥ **4 次** | 断到四次就是在把好几件事塞进一句，读到中间忘了开头 |
| `noun-pile` 整句只有名词 | ≥ **24 字** + 抽象名词叠 ≥ **2 种** + **一个动作都没有** | 「字都认识、读完不知道在说什么」；三个条件同时成立才算——单看长度或单看名词都会误伤好句子 |
| `bureaucratic` 公文体 | 「该操作…」/「被…执行」/「处理流程已终止」 | **绝对挡，不记预算**：制度文件里才有的话，她不会这么说话 |
| `vague-pronoun` 指代不明 | 句首的 它/该/此/其 + 状态（已经/已/正在…） | **绝对挡，不记预算**：她不知道到底是谁准备好了 |
| `passive` 被动句 | 含「被」 | 被动不点明谁做的；但王姐场景里有几处被动**是唯一准确**的说法（见下） |

**动作词表**（`noun-pile` 用）**只收多字词（≥2 字）**，这是有意的：中文没有词
边界，单字动词会到处误命中——「关」命中「关于」、「说」命中「说明」，于是
「关于数据状态的说明」反而被算成有两个动作。收单字的结果是**既误报又漏报**，
不如只收多字短语。中文动词名词同形（整理 / 保存）的词都收：多算只会漏判，
不会把一句有动作的好句子误判成没动作。

## 3. 不误伤：白名单 + 理由

被动句里，有几处**被动是对的**，不该为了数字好看去改：

- 文件**正被 Excel 或 WPS 打开**——占用它的是哪个程序，正是她要去关的那个窗口；
  主动句没有更清楚的说法；
- 文件**可能被移走 / 删掉**——谁挪走的我们看不见，她要的是「它不在了」；
- **原来的文件没有被改动** / **不会被改动**——这是产品律 2 的承诺**原话**，
  改成主动会丢掉「我们没动它」这层保证。

这些都逐条列在 `readability.test.ts` 的 `PASSIVE_ALLOW` 里，每条写清为什么。
**一条白名单一旦不再命中任何句子，测试会要求删掉**——免得例外只增不减（和
copy-guard / tone 的做法一致）。

## 4. 扫描范围（和 copy-guard 刻意不同）

扫 `gui/src/simple/copy*.ts` 里的字符串字面量，但：

- **包含 `copy-capability.ts`**（copy-guard 当年因 workstream 归属排除了它）。
  它面向用户（表格 / PDF / 图片读不了时给她看的话），而现状里**最长的几句恰好在
  里面**——少扫它等于把最难读的句子排除在闸门之外。
- **排除两类"不是给她看"的字符串**：属性名是 `envelope` 的是发给助手的指令；
  `new RegExp(…)` 的模板是给程序看的特征。两者都不是界面文案。
- 正则字面量、注释不算。

## 6. 预算表：只许减不许增

`readability.test.ts` 的 `BUDGETS` 把每格难读句子的数量**冻结在现状**：

- 长句：`copy-capability.ts` 4、`copy.ts` 4、`copy-preanswer.ts` 2、
  `copy-privacy-audit.ts` 1、`copy-daemon.ts` 1（合计 12）；
- 断句多：`copy-capability.ts` 1、`copy-preanswer.ts` 1（合计 2）；
- 整句只有名词：**0**（现状一条都没有，出现一条就是失败，不列预算格）；
- 被动句：白名单之外 **0**（现状没有未审的被动句，写 0 上界）。

谁改文案时让某一格涨上去，CI 就红，他要么把那句改短，要么**说明为什么必须这么长**
再调大数字。往下降就连带把数字改小——`copy-guard.test.ts` 的台账是同一套做法。

## 7. 边界（最重要的一节）

**这个闸门只能证明"这几句没有明显的难读特征"，不能证明"她真的看懂了"。**

- 数字筛掉的是**长、绕、没动作、公文腔**这类可量化的毛病；
- 一句**短而清楚**的话到底好不好懂、按钮放得对不对、她会不会在某个词上卡住——
  **只有真人测试能给答案**（找 3–5 个画像内的行政/财务，看她读着做一遍）。
- 「真人测试做了没有」不在本闸门能回答的范围内，也不是它该假装回答的。

换句话说：**过了闸门 ≠ 没问题，只是没有"机器看得出的那种问题"。**
说"她能不能看懂已经验证过了"之前，先问一句："**我看的是真人做出来的结果，还是
只是数字过了？**"
