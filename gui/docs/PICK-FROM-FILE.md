# 她手里拿着一个文件，不知道能用它做什么（P1）

这份文档回答的是**事实**，不是设想：选完文件之后她到底看得到什么、卡库现在支持哪些
找卡的说法、以及「手里一个 .xlsx，从打开应用到开始做」最少要点几下、要不要先选卡。
每一条都对着今天的代码核过（写清文件与行号）。

实现的判据在 `gui/src/simple/pick.test.ts`；这一篇是**理由与现状**。

---

## 1. 她的处境和卡库的组织方式是反的

- 卡库（首页 33 张卡）是**按任务名**组织的：「把几张表合成一张」「按类别汇总并配上
  图表」。要走进一张卡，得先说出**这件事叫什么**（`README.md`、`ROADMAP.md` §1）。
- 她的真实动作常常相反：**手里刚拿到一个文件**（微信发来的报名表、同事给的账单），
  不知道该选哪张卡。这时她只能去卡库里**逐个读卡名**猜。

`catalog.ts` 已经有「按词找卡」的底子（`SYNONYMS` 同义词表），但那个入口在**能力
中心**里（`TaskLibrary`），不在「我刚拿到一个文件」这条路上。

---

## 2. 选完文件之后，她原来实际能看到的（逐条，改之前）

确认页是 `ConfirmSheet.tsx`，她在「选文件 → 下一步 → 生成计划」之后落到这里。改之前
这一屏**从上到下**画出来的是：

| 位置 | 内容 | 出处 |
| --- | --- | --- |
| 顶部 | 「动手前，先给你看一眼」+ 这张卡的标题 | `ConfirmSheet.tsx` header |
| 「它打算这样做」 | 这张卡的**固定计划**（不是模型现编的） | 卡片 `plan` |
| 「动手前先定好这几件事」 | 只有登记过的卡才有（合并/对比/整理/汇总） | `copy-preanswer.ts` |
| 「这个任务可能不准的地方」 | 这张卡写死的、能对着自己文件核对的风险 | 卡片 `risks` |
| 绿色框（有历史时） | 「这个任务你做过 N 次，成功 M 次」 | `evidence.ts`（#64） |
| 「要处理的文件（N 个）」 | 文件名 + 「不用这个」；超过 6 个折叠 | `copy-files.ts` |
| 「已经去掉的（你的文件还在原处）」 | 去掉过的 + 「加回来」 | `copy-files.ts` |
| 边界说明（按情况） | 读不了 Excel / PDF / 看不了图时的一句中性说明 | `copy-capability.ts` |
| 「这几份文件我打不开」 | 交来的是 WPS / 苹果自己的格式时（#88） | `format-check.ts` |
| 「会影响什么」 | 删/覆盖/发消息四格 + 「发消息一律是 0 条」 | `run.ts` `planRisks` |
| 红色警示 + 覆盖勾选框 | 这次会动原文件时才出现 | `ConfirmSheet.tsx` |
| 页脚 | 「先给我看一眼（只看不动）」+「取消」+「开始」 | `copy.ts` TRY_FIRST |

**结论**：改之前，这一屏只展示**她已经选好的那张卡**要怎么做——**没有**「这个文件
还能拿来做哪些别的事」。她要是选错了卡，出路是返回首页、回能力中心重新找。

---

## 3. 卡库里「按词找卡」现在支持哪些词、认不出来会怎样

两套函数都在 `catalog.ts`，用的是同一张同义词表 `SYNONYMS`（20 组，见下）：

- `searchTasks(query)`——**宽**：命中卡标题（3 分）、组名或示例（2 分）、计划步骤或
  结果提示（1 分），按分数排。空词返回全部。
- `suggestTasks(query)`——**窄**：只认**卡标题与示例**（不认组名/计划），一张都不像就
  返回空数组，最多 3 张。这是她说了一句话、还没点卡时那句「你是想做这个吗」的判据
  （`copy-suggest.ts`）。

`SYNONYMS` 的 20 组（每组里的说法任意一个触发，整组都拿来匹配）：

合并/汇总、去重/重复、对账/核对/比差异、筛选/挑出、拆分/拆列、改名/重命名、归档/按
月份、微信/群/聊天、pdf/扫描件、图片/照片/截图、总结/摘要、通知/请假/周报、
检查/合计/算错、发票/报销、考勤/打卡、花名册/员工、到期/续签、接龙/报名/没交、
盘点/库存、政策/资料。

**认不出的词会怎样**：搜索词命中任何一组同义词都没有时——

- `searchTasks` 返回空数组；
- 界面上（`TaskLibrary.tsx`）先看 `suggestTasks`：也没有 → 显示「没找到你要做的事 /
  换个说法再搜一次，或者回首页用一句话说给我听」，并给两个按钮（「换个说法再搜」
  「回首页说一句话」）。**不硬凑**。

## 4. 手里拿着一个 .xlsx：最少要点几下、要不要先选卡

**要。今天必须先选定「要做哪件事」**——不管是点一张卡，还是在首页说一句话；说一句
认不出来的话也会走「自由任务」（`freeTask`），它同样**需要文件**，一样要从选文件这一步
开始。所以「完全不做选择题、直接拿文件开始」这条路**目前不存在**。

最短的一条路（点卡，`TaskRunner.tsx` 的四步 pick → say → confirm → result）：

| 第几下 | 点什么 | 落在哪 |
| --- | --- | --- |
| 1 | 首页上一张卡 | 选文件那一步 |
| 2 | 「选择文件」（再到系统窗口里选那一个 .xlsx 并确认） | 文件进列表 |
| 3 | 「下一步」 | 说需求那一步 |
| 4 | 「生成计划」（她可以先打字，也可以点「就照这个例子来」） | 确认页（`ConfirmSheet`） |
| 5 | 「开始」 | 真的动手 |

也就是**应用内最少 5 下**（外加系统文件窗口里那一次确认，以及第 4 步要有一句话）。
她**要先把卡选出来**。

> 打印计划那一步之前必须先有一句话：确认页展示的是「这张卡 + 她那句话」拼出来的
> 事情。这一步没有可省的余地。

## 5. 本轮加的那一步（B 部分）

在**确认页**（就是上面第 4 步落地的那一屏）加了一块「这个文件可以做的事」：

- **位置**：在文件列表下面、边界说明上面（`ConfirmSheet.tsx`，只在**需要文件的卡、
  手里真有文件、且不是微信那族**时出现）。
- **几条**：最多 **5** 条（`pick.ts` 的 `MAX_PICK_SUGGESTIONS`）。她选不出来时，多给
  一条都是负担。
- **每条是什么**：一句**人话**（不是卡名），例如 xlsx →「把这几张表合成一张」「按类别
  汇总一下」「核对一下合计对不对」「两张表对一下账」「从表里挑出想要的行」。
  文案在 `copy-pick.ts` 的 `PICK_SENTENCES`，键是**真实的卡片 id**。
- **点一下等于什么**：等于**把这次换乘那张卡**（`store.startRun`）——文件和她刚说的话
  都带过去，计划换成那张卡的固定计划。**复用现有卡，绝不新造任务**，也不会绕开确认页
  直接动手（换完仍然停在确认页，要她自己点「开始」）。
- **认不出的类型**（没后缀、`.exe` 这种）：返回空列表，界面照实说「这种文件我没有现成
  能做的事。你可以用一句话说给我听。」——**不假装知道**。

按文件类型给的三组（`pick.ts` 的 `BY_KIND`）：

| 文件类型 | 认哪些后缀 | 给的事（按想做的先后） |
| --- | --- | --- |
| 表格 | xlsx / xls / csv | 合成一张、按类别汇总、核对合计、两表对账、从表里挑行 |
| PDF | pdf | 发票台账、拆开、合起来、转 Word、总结要点 |
| 图片 | jpg / jpeg / png / heic / heif / webp / bmp / tif / tiff | 把图片里的表格抄成 Excel |

（这几组后缀不是另抄一份清单，而是取**卡片自己的 `accept`**（代表卡：`excel.merge` /
`pdf.merge` / `vision.table`）——后缀只有一处真相，卡片改了这里跟着变。）

（图片这一类**只有一条**：现在从图片里认字还受通道限制，见 `ROADMAP.md` 的诚实边界。
一条也是对的——多凑几条只会让她以为还有别的能做。）

## 6. 这一轮改了什么、没改什么

- 新增：`gui/src/simple/pick.ts`（纯逻辑）、`gui/src/simple/copy-pick.ts`（文案）、
  `gui/src/simple/pick.test.ts`（断言）、本文件。
- 改动：`ConfirmSheet.tsx`——只加「这个文件可以做的事」这一块（+ 一个 `useIdea`
  处理函数与两个 import）。
- **没碰**：`tasks/**`（加卡是别的事）、`store.ts`、`tauri.conf.json`、workflows。

## 7. 这一篇没能说的

- **真 Windows / 真 WebView2 上点一下的观感**：本机只跑到无头 Chrome（`dom-smoke.sh`
  的 `tryfirst` 那一步），见 `gui/VERIFICATION-MAP.md` 第一节那几行「不覆盖」。
- **她会不会真的看懂、会不会点**：只有真人测试能给答案。这里能证明的是「按类型给的
  建议不串台、都指向真卡、最多 5 条、认不出就说不知道」（`pick.test.ts`）。
