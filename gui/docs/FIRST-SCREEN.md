这份文档只回答一件事：**真的装好、真的第一次打开**时，王姐（画像见 `ROADMAP.md` §1）
第一眼会读到的**全部文字**是什么。

为什么单独写这一份：`copy-guard` / `typography` / `tone` / `dom-smoke` / 真机 UIA 都在挡
「我们以为的界面」；**没有一处**是从**产物**那一侧、把第一屏的**逐字全文**抄下来核过。
这份文档补的就是这一格。事实来自**构建产物真的渲染出来的那段 DOM**（不是源码里的字符串，
也不是"看起来接好了"），方法见 §1。

**本轮结论：只交文档，不动任何文案、不动任何界面。** 依据见 §6。

## 1. 这些字是怎么拿到的（可复现）

走的是 `gui/scripts/dom-smoke.sh` 同一条真实路径：**构建产物 `dist/` + 本地静态服务 + 无头
Chrome `--dump-dom`**，探针从真实页面里把可见文字读回来（不是源码扫描）。

```bash
cd gui
bun run build:web                      # 产物在 gui/dist
# 之后用 dom-smoke.sh 的同一套：本地起 serve.py 服务 dist，Chrome --dump-dom
bash scripts/dom-smoke.sh              # 门禁里就是这么跑的（e2e 第 9 步）
```

本轮的逐字全文来自对 `gui/dist` 的一次单独渲染（探针把 `document.body` 里**可见**的文字节点
按阅读顺序读出来），四个入口各一次：

| 入口 | 触发方式 | 对应的产品状态 |
| --- | --- | --- |
| 首启向导 | 直接打开 `/`（无任何标记） | **装好后第一次打开**（默认就这一条） |

## 2. 两个入口，分别在什么条件下出现

`Wizard.tsx` 的 `shouldShowWizard()` 是三件事同时为假才显示向导：

```ts
return !readFlag(WIZARD_DONE_KEY)        // localStorage "cante:wizard:done" 不是 "1"
    && !isProvisioned()                  // "cante:provisioned" 不是 "1"，也没有 window.__CANTE_PROVISIONED__===true
    && !adminConfigured();               // ~/.cante/admin.json 读到的 present 不是 true
```

- **刚装好、什么都没配的机器** → 三条全假 → **向导第 1 步**。这是"第一次打开"的默认形态。
- **技术同事预置过的机器**（`~/.cante/admin.json`，企业预置 `#58`）→ `adminConfigured()` 为真
  → **直接进首页**，看不到向导。

**`__CANTE_PROVISIONED__` / `cante:provisioned` 谁设的：产品里没有任何东西设它们。**
`git grep` 全仓库（`gui/src`、`gui/src-tauri`、安装脚本、构建脚本）只有一个**读**方
（`Wizard.tsx`），**写**方全部在测试/量测脚本里（`dom-smoke.sh`、`measure-web.sh`、
`zoom/serve.py`）。所以 `dom-smoke.sh` 里那条 `/?provisioned=1` **不是**生产路径的触发器
——生产上让向导消失的是 `admin.json`（`admin_config` 命令，`DEVELOPING-WINDOWS.md` §首屏验收
也这么写）。`Wizard.tsx` 的注释把这个 JS 标记列为一条**可选**入口（"An administrator (or a
packaging script) can set either the localStorage key or `window.__CANTE_PROVISIONED__`"），
但**仓库里没有任何打包/安装脚本真的写它**：这是一条**有读方、无写方的能力**（不是 bug，
但下一个人要知道真机上它不会被触发）。本轮**不改**它——不在改动范围内。

## 5. 三句判据（对着画像问，逐句给结论）

**问 1：她完全不懂电脑术语，这些字她每一个都认得吗？**
**结论：认得，每一个都认得。** 依据：§3.1 的 10 个字串全是常用中文 + 产品名；§4 的黑名单
扫描零命中。没有一处需要她"先懂一个词"。

**问 2：她第一屏需要做决定吗？**
**结论：需要，但只需要一个，而且那个决定她看得懂。** 第一屏共 4 个可点控件，但产品**要求**
她做的决定只有 1 个——按不按「开始检查」（其余 3 个是头部入口，不按也能往下走）。这一个决定
不需要背景知识。依据：§3.1；第 1 步在**大、小、以及最小允许窗口**（1180×760 / 800×560 /
760×520）下都实测过，控件全部够得着、没有零尺寸或裁切（探针逐控件量过）。

**问 3：她什么都不敢点就关掉了，下次打开会看到什么？**
**结论：会看到同一屏欢迎（不是吓人的东西），而且不会丢任何东西。** 依据：我用**同一个
浏览器档案**连开两次，两次都渲染出 `欢迎使用 Cante`，`cante:wizard:done` 两次都是 `null`
（她没点「开始使用」就不会被记成"做完了"，所以向导会**照常再出现**——这是对的：她确实还没
走完）。上一次打开时若在第 3 步点过例子却没点「开始使用」，那句话也会被 `beginFirstRun()`
在向导一露面时清掉（`Wizard.tsx` `onMount`），**不会**在下次打开时冒进首页输入框。

**一条相邻的边界（她点了那一下、不是"什么都没点"）**：这台电脑**组件齐全**时，她只要按
第一屏唯一那个「开始检查」，`runCheck()` 里那行 `if (daemonReady(cap)) markWizardDone()`
**当场**就把 `cante:wizard:done` 记成 `1`（实测：点完按钮 `wizard:done='1'`，这一屏还停在
「已经就绪」）。所以：**她按了按钮、看了一眼「已经就绪」、不敢再按「下一步」就把应用关掉
——下次打开直接进首页**（实测同一档案连开两次：第一次点完是 `检查你的电脑`，第二次就是
`你好，需要我帮你做什么？`），**三条承诺和三句例子她这趟就没看到**。缺组件那一支**没有**
这个效果（实测：走到第 3 步 `wizard:done` 仍是 `null`，她没点「开始使用」就不会被记完成）。

> 这是**行为上的不一致**（同一屏，取决于一个她看不见的机器事实，决定她能不能看到信任那段），
> 但它是 `Wizard.tsx` 的**逻辑**（`markWizardDone` 的调用时机），不在本轮的改动范围里
> （硬约束：「`Wizard.tsx` 只改文案相关，别动逻辑」）。所以本轮**只如实记下**，交给集成者
> 判断：修它要先决定「按了开始检查就算走完向导」是不是有意的（`#150` 之后的注释显示是有意的）。

## 7. 没验的（与"验了"分开写）

- **真机 WebView2 上的第一屏逐字全文**：我读的是 **Chrome 渲染的产物 DOM**（macOS，headless）。
  真 Windows 上 `accept-first-screen.ps1` 用 UIA 读第 1 步，但那不是在**这台** macOS 机器上跑
  的、我这轮也没跑；而且 `VERIFICATION-MAP.md` 已写明：Linux/本机 Chrome 与她的 WebView2
  **不是同一个渲染器**。所以"这份逐字全文在真 WebView2 里一字不差"**没验**。
- **显示缩放（125% / 150%）下的第一屏观感**：`dom-smoke` 不覆盖缩放（地图里明写）；
  `zoom/driver.py` 量的是**首页/能力中心那一面**（`?provisioned=1`），**没有量向导第 1 步**。
  我的向导小窗口测量只有 100% 缩放。
- **向导第 2 步「已就绪 / 缺组件」两支的真机渲染**：§3.2 的逐字来自我用**替身桥**在真实页面里
  渲染出来的（`daemon_capability` 返回真实 Rust 会返回的 `why`），**不是**真机跑出来的。
  真机上"缺组件时向导怎么显示"在 `WINDOWS-ACCEPTANCE-21.md` 里**明确记为没验**。
- **字体手感、中文排版、动画、鼠标真点像素**：一条都没验（UIA 与 DOM 都证明不了观感）。
