# 第 9 批机会点：**她关掉应用的那一刻**

起点：第 8 批（#256）已合并 ✓，0 个开着 PR ✓。这批先核了三个怀疑点 ✓，**两个成立** ✓。

---

## P0 · 她**正在做**的时候关掉应用，回来像个没事人 ✗（**新**）

**核过的事实链**（每一环都有出处 ✓）：
1. 应用退出时只 `drop` 守护进程的 stdin（`daemon.rs:407 Drop for Daemon`）✓ —— 进程收 EOF 收敛 ✓，
   但**手里那件活就是被丢下的** ✗；
2. 那条 run **只在结束时才落盘** ✓（`files.rs:675` 注释明写 "Persist a **finished (or failed)** run" ✓，
   `store.ts:1431` 的 `persistRun` 只在 `finishRun` 里调 ✓）；
3. 所以重开之后，**磁盘上一条记录都没有** ✗；
4. 首页的"上次有件事没做完"（`resume.ts` ✓）只认 `failed`/`cancelled` ✓，**根本没有记录可认** ✗；
5. 结果：她重开应用，**一句话都没有** ✗ —— 她以为在做，其实早停了 ✗（产品律 1：把麻烦事做完 ✗）。

**为什么是 P0**：这不是"少一句话" ✓ —— 她**会一直等** ✗（画像第 3 条：她出错时无法自救 ✓）。
而且她**完全无法知道**：界面上没有任何东西说"上次那件没做完" ✗。

**要做**（两个方向都要，缺一不可 ✓）：
- **A 落盘**：开做时就**记一条"正在做"** ✓（`save_run` 已有 upsert ✓），这样即使被杀，
  重开后能看见"上次这件**半途停了**" ✓；下次这一轮正常结束时覆盖它 ✓。
- **B 说出来**：重开后把"半途停了"这条**说清** ✓（发生了什么 + 她可以怎么做：**再跑一次** ✓，
  并说明**原来的文件没有被改** ✓ —— 这一条要说，因为她最怕的就是"做到一半的文件坏了" ✓）。

**不做** ✗：不做"自动接着做"✓（红线：动手要她点头 ✓）；不做关闭拦截弹窗 ✓（先别打扰她 ✓，
那是另一个决定，留给下一批 ✓）。

## P1 · 她关掉应用时，**没有任何东西拦一下** ✗（**新**）

**核过**：全仓库 grep `beforeunload` / `onCloseRequested` / `ExitRequested` ✓ **全空** ✗。
她正在做的时候点右上角 X ✓ → 应用直接没了 ✗（做的活也停了 ✓）。
**要做**：先**只做最小的一步** ✓ —— 正在做的时候退出，**加一句确认** ✓
（"现在还有一件事没做完，关掉就会停下来。要关吗？"✓ 默认焦点在"不关"✓）。
**不做** ✗：不阻止她关 ✓（她有权关 ✓）、不记"她强行关了"这种状态 ✓。
