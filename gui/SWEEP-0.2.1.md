## 1. 这次是怎么跑的（以及为什么这么选）

### 1.1 为什么用"已发布的 0.2.1"而不是"从 main 编一个"

任务允许二选一。选**装 v0.2.1**，理由是本次要回答的正是**发出去的那个东西**行不行：
从 main 编出来的包和用户下到的包不是同一个字节，验后者才对应那条承诺。

### 1.3 运行时与"两个核验工具怎么接上"

- 运行时用 **WSL 里的 `ante`**（这台机器上唯一能提供守护进程的地方）；
- 所以整个普查（python + bun + 提示词函数）都在 WSL 里跑，它生成的路径才是 Linux 路径；
- 而**读回产出**用的两个工具是 Windows 的 `.exe`。做法和每周普查一样：两个十行的**路径翻译垫片**
  （把参数里的 Linux 路径 `wslpath -w` 翻一次再 `exec` 那个 `.exe`），通过
  `CANTE_SHEETS_BIN` / `CANTE_PDF_BIN` 交给普查。垫片与工具副本这次放在 `C:\sweep-021\`（仓库外）。

## 4. "停下问问题"这 4 张，问得对不对

**先说结论：4 张里 3 张问得对，1 张问得有理但不划算。**

1. **`pdf.toword[扫描版]`——问得对。** 它先用 `cante-pdf pages` / `cante-pdf text` 试了，
   工具明确回"这份 PDF 里没有文字层（大概是扫描或拍照的）"，它没有硬转、也没有假装成功，
   而是把"扫描件 → 不能直接转"这件事说清楚并给出选择。这正是卡片风险和共用规矩里
   「看不懂就先停 / 缺工具先说」要求的行为。

2. **`doc.leave[原话]`——问得对。** 原话场景本来就只给一句"下周三请一天事假，带我妈去医院复查"；
   它先把请假条该有的信息列清楚、把"下周三"换算成具体日期，然后交代**这台电脑没有能写 Word 的工具**、
   打算存成纯文本，再停下来问。信息不全 + 工具受限，两件事都该说。

3. **`doc.report[原话]`——问得对。** 原话里只有"客服系统上线"一条线索，它列了 4 个问题
   （给谁看、这周还做了什么、上线的实际进展与数字、卡在哪），并且明说"没有数字就不编"。
   这跟基线里同一张卡的表现一致。

4. **`doc.report[信息齐全]`——问得有理，但不划算。** 这一张给的信息是齐的
   （汇报对象、时间、事项、数字 8→3 分钟、问题、下一步都给了），它**没有**再问那些已经答过的问题
   （这是对的），但把整轮花在了一句「汇报人（您）的名字和部门要不要写在开头？」上——
   **3 秒、0 次工具调用、没有产出**。

   为什么说"有理"：卡片共用规矩里写着「先把用户原话里已经有的信息理出来（写给谁、什么事、时间、
   **名字、部门**），缺少的关键信息**先问我**，不要自己编」（`gui/src/simple/tasks/document.ts` 第 12 行），
   而这一条场景确实没给名字与部门 —— 按这行的字面意思，它**应该**问。

   为什么说"不划算"：① 场景名字叫「信息齐全」，意图就是"信息够全了，别再问"；
   ② 同一张卡的风险列表里已经写了另一条出路——「没有的数字和成绩，我不会编；这些地方会留空并提醒你补」，
   署名完全可以按这条办（先写出来、把署名留空、在结果里提醒）；
   ③ 对用户来说，为了一个署名多等一轮，是"白等"。

   **这是卡片提示词内部的一处冲突，不是助手的错**（"关键信息"里到底该不该包含署名，卡片自己没有统一）。
   建议交给这张卡的所有者决定：要么把"名字、部门"从"缺少就先问"的清单里去掉，
   要么承认「信息齐全」这个场景在当前提示词下**必然**会问、把它的期望结论改成"停下问问题"。
   **这一轮按任务要求没有动任何产品代码，只把现象与证据记在这里。**

## 8. 我没能验证什么

**这一节和上面的结论一样重要。**

1. **应用在真实界面里的样子**：这一轮的普查走的是"真守护进程 + 真模型 + 真文件"，**没有经过界面**。
   界面上的字号、排版、点击手感、有没有闪黑窗，以及"她在界面上点完一张卡"这条链，这次一条都没验
   （我是 SSH 会话，没有交互桌面）。
2. **那 12 张没进计划的卡**（§5）——不是"过了"，是**没跑**。
3. **单次样本分不清"回归"与"随机"**：26 次运行各只有一次。差异表里的"这次好了 4 张"和
   "`doc.report[信息齐全]` 这次问了"都可能是随机波动。要下因果结论，需要对同一张卡重复跑几轮。
4. **`wechat.table` 的"通过"是复跑的结果**（§6），不是同一轮连续跑出来的。
5. **0.2.1 只验了 NSIS 包**：这一轮没装 MSI 那个产物（上一次验收两个都看过，载荷一致）。
6. **计划任务在"长期没人登录"时的行为**：只确认了任务在、上次跑过、报告在；`StartWhenAvailable`
   在机器一直没人登录时的表现**没有验证**（要等真的过一周）。
