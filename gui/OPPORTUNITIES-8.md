## P1 · 文件在 U 盘 / 移动硬盘上，盘拔了以后她看到的话是错的 ✗（**新**）

**判据（核过 ✓）**：
- `gui/src-tauri/src/files.rs:608 open_path` 开头就是 `if !Path::new(&path).exists()` ✓ →
  一句 `这个文件找不到了：{path}` ✓；
- `gui/src/simple/copy-results.ts:86` 接着把它翻译成
  「这个文件现在找不到了：它可能**被移动或删掉了**」✗ —— **一个字都没提"盘可能拔了"** ✗；
- 而她的处境是：文件在她自己的 U 盘上 ✓，她**明明插着**（或以为插着 ✓），
  屏幕上却说"被移动或删掉了" ✗ → 她会去**重选一份本来好好的文件** ✗，
  甚至以为"是不是我把它弄丢了" ✓（画像：她出错时无法自救 ✓）。

**要做**：
1. **先核事实**：`Path::exists()` 在"父目录都还在、只是文件没了"与"整个盘不在了"两种情况
   下**能不能分开**（Windows 上盘符消失 vs 路径不存在、macOS 上 `/Volumes/...` 卸载 ✓）；
   核出来的结论写进 `gui/docs/MISSING-FILE.md` ✓，**核不出来的写"没核出来"** ✗ 别猜 ✗。
2. 若能分开 → 让那句话**说出第三种可能** ✓：「这个文件在**一个现在没连接的盘**上（比如 U 盘、
   移动硬盘）。把它插回来，再点一次。」✓（**具体的下一步** ✓）
3. 若分不开 → **至少**别把话说死 ✗：把"被移动或删掉了"改成**包含**"或这个盘现在没接上" ✓，
   并给两步出路（插回那个盘 / 重新选文件）✓。
4. 断言：三种情形（文件没了 / 盘不在 / 认不出）各自落到不同说法 ✓；认不出退回通用 ✓；
   **不许**出现"文件被删了"这种**没有依据**的断定 ✗。

## P1 · 双击两次开出两个 Cante ✗（**新**）

**判据（核过 ✓）**：`gui/src-tauri/Cargo.toml` 里**没有** `tauri-plugin-single-instance` ✗，
`lib.rs` 里也没有相关 handler ✗ → 她双击两次（或者双击了图标又点了任务栏 ✓）
就会开**两个**窗口 ✗，两个都持有自己的守护进程与快照 ✓ →
「撤销」看到的事实可能是**对方进程**造成的 ✓（**这是"别弄坏我的东西"那条律** ✓）。

**要做**：**先核**（别直接改 ✗）：
1. 两个实例**真的**会互相干扰吗 —— 读 `files.rs` 的 `store_root` / `write_runs` / 快照目录 ✓，
   判断两份进程会不会**同时**写同一份记录（会不会互相盖 ✗）；
2. 结论写进同一份文档 ✓；
3. **只在确有干扰时**才加**最小**的修 ✓：加 `tauri-plugin-single-instance`（第二次启动就
   把**已有窗口**bring to front ✓、**不带参数**开新窗口 ✗），
   **主副实例都不许改动她的文件** ✓；
4. 断言：第二次启动**不开新窗口** ✓、**已有那个被激活** ✓、**新进程不启动第二个守护进程** ✓。
