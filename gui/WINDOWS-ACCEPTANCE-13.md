# 第十三次真机验收：「服务方真的没了」的三种错法（#197 P1）

> 这一轮要证的是 #173 留下的缺口：桥在服务方静默时会如实说「连不上」，但那次**没有真拔网线**，
> 而「公司网络挡住」是**完全不同的一种错法**（`ROADMAP §6.5`：她办公室的现实）。
> 所以本次在真 Windows 上**摆出三种现场**，记录**她屏幕上逐字出现的话**、以及**有没有一个她真能做的动作**。
>
> - **验收对象**：**当前 `main`（`1bc702e`）** 自己构建的 `cante-gui`（debug，`cargo` + `vite` 现场构建；
>   版本号仍是 `0.2.3`）。**不是**已发布的 0.2.3 安装包 —— 两者在 #173 之后有实质差异，见 §5。
> - **验收机器**：Windows 11 家庭版 / `10.0.26200` / x64（QEMU/KVM 虚拟机）；WebView2 `153.0.4234.46`；
>   msedgedriver `153.0.4234.46`（与运行时同版本 → 会话一次就建起来）
> - **验收人**：跑在那台机器上的 pi —— **不提权的交互会话**（`elevated=False session=1 有桌面=True`），
>   所以就地跑，没有走计划任务那条路
> - **起始提交**：`1bc702e`；**工作分支**：`pool/win-offline`
> - 每次跑完都核对**原文件 sha256**；三种现场**三次都一致**（§2）
> - 所有长命令都带超时；超时与「确认没有」分开写

   退出码 **1**，两条代理场景落在文件问题上）。
6. **文件安全**：三种现场、每次跑完，输入表 sha256 **前后一致** ✓（§2）—— 产品律没被破。

## 1. 三种现场是怎么摆的（要脚本可重复）

三个场景都只改**一件事**：把应用用的模型端点指到一个我们摆的服务方上。
改法**不动**这台机器真正在用的 pi 配置，而是给这一轮一个独立配置目录
（`PI_CODING_AGENT_DIR`），里面的 `models.json` 把 `baseUrl` 指到某个本地端口。

| 现场 | 服务方长什么样 | 端口的可见状态 | 脚本 |
| --- | --- | --- | --- |
| **dead** 端口不可达 | **不起任何监听**（端口上没人听，TCP 握不上手） | `TcpTestSucceeded=False`（实测） | `relay.mjs dead` |
| **cut** 中途断掉 | 正常答完**第 2 个工具调用**后**静默**：不写一个字节、不发 FIN、不关 socket | `True` | `relay.mjs cut` |
| **forbid** 代理挡住 | 每个请求都回 **403**，正文是网关那种英文说明 | `True` | `relay.mjs forbid` |

`cut` 的造法照搬 bridge 集成测试里那个 `stall` 现场（`gui/src-tauri/tests/bridge.rs` 的原话：
"the cut lands with two completed calls behind it" / "nothing is ever written and the socket is held open
(no FIN), which is what a dead network looks like to the client"）—— 所以它验的是**同一个物理现象**。

一次现场怎么跑（一条命令）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File gui\scripts\windows\run-offline.ps1 -Scenario dead
powershell -NoProfile -ExecutionPolicy Bypass -File gui\scripts\windows\run-offline.ps1 -Scenario cut    -StallSecs 45
powershell -NoProfile -ExecutionPolicy Bypass -File gui\scripts\windows\run-offline.ps1 -Scenario forbid
```

它自己：把当前构建的应用**复制到隔离目录**（原因见 §5）、清残留子进程、摆假服务方、
起 WebDriver、在真 WebView2 里点一张卡（`从大表里挑出想要的行`）、自动应答审批，
一直跑到**结局页**（成功/失败都算结局），把**文字 / HTML / 截图**落盘，最后核对原文件 sha256，
并核对**现场真的摆上了**（注入哨兵，见 §6 第 4 条）。

**「她屏幕上那一屏」是怎么取到的**：`ErrorView` 的 `body` 文字（`getText()`）、整页 HTML、截图，
三者都落盘在 `artifacts/outcome-<结局>.{txt,html,png}`。下面 §3 的原文就是 `.txt` 的逐字内容。

> **一个必须说清的取舍**：`CANTE_BRIDGE_STALL_SECS` 默认压到 **45 秒**（产品默认 **600 秒**）。
> 压它的唯一理由是「让停滞在可观测的时间尺度内发生」；它只改**触发时间**，不改**触发后说什么**。
> 报告里凡是引用停滞原文的地方，都同时给出实际用的阈值。
> 另外，**`dead` 不需要这个阈值**：端口不可达时 pi 立刻报错（实测约 14 秒），走的是即时失败那条路。

### 3.3 forbid —— 公司网络挡住 / 403（**不符合**判据 ✗✗）

```
这次没能做完
发生了什么
这件事没有做完。
你可以怎么做
原来的文件都还在。可以再试一次，或者换一种说法告诉我要做什么。
→关掉那个窗口再试
这个文件正被 Excel 或 WPS 打开着，所以改不动。先把那个窗口关掉，再点这个按钮。
复制详情
把下面那段原始说明复制出来，发给懂电脑的同事，让他帮你看看。
这个文件正被别的程序占用着，现在改不了。
先关掉打开它的程序（例如 Excel 或微信），再点「重试」。
展开技术详情
```

**这一场不许过** ✗：

- 她被告知「**这个文件正被 Excel 或 WPS 打开着**」——**根本没有这回事**。这一场的原文是
  `403: {"message":"Forbidden: blocked by corporate proxy","type":"proxy_error","code":403}`
  （「技术详情」里原样能展开看到，逐字）。
- 她被告知的动作是「**关掉那个窗口再试**」——**这一步在她的处境里不存在**（没有那个窗口可关）。
- 判据要求「**不许**把网络问题说成文件问题 ✗✗」——**这一条红了**。

**真因（可核对，不是猜）**：`src/simple/recovery.ts` 的 `BUSY` 规则里有一条 `locked by`：

```
/being used by another|resource busy|\bEBUSY\b|file is locked|locked by|locked for writing|another program…
```

而**代理/网关挡住**最常见的英文写法是 "**b**locked by"（`blocked by corporate proxy`、
`blocked by policy`、`blocked by Zscaler` …）—— `locked by` 正好是它的**子串**。
于是 `BUSY.test(原文)` 命中，`actionsFor` 在**走到 AUTH/NETWORK 之前**就把它归成了「文件被占用」。

**为什么以前没被发现**：`recovery.test.ts` 里 BUSY 那几条用的都是
`EBUSY: resource busy or locked` / `~$报表.xlsx` —— **全是真正的文件占用**，
没有任何一条测试用过 "blocked by" 这种代理写法。所以这一条**一直是绿的**，
而真机上第一次造出「公司网络挡住」就红了。

**判据脚本（可重复、直接 import 产品模块）**：

```bash
cd gui && bun scripts/windows/offline-probe/classify-assert.ts
```

它不抄正则，而是 import **产品自己的** `recovery.ts` / `copy.ts`，对一组真实错误原文断言分类：

```
✗ 代理挡住（403 + blocked by，最常见的公司网关说法）  → 按钮：关掉那个窗口再试 / 复制详情
✗ 代理挡住（403 + blocked by policy）                 → 按钮：关掉那个窗口再试 / 复制详情
✓ 端口不可达（Connection error.）                    → 按钮：过一会儿再试 / 复制详情
✓ 端口不可达（ECONNREFUSED）                         → 按钮：过一会儿再试 / 复制详情
✓ 中途断掉（桥报的停滞原文）                          → 按钮：再试一次 / 复制详情
✓ 真的文件被占用（对照：这条**应该**是文件问题）        → 按钮：关掉那个窗口再试 / 复制详情
classify-assert: 2 条不符合判据
```

（退出码 **1**。最后那条对照很重要：修的时候**不能**为了修前两条，把真正的文件占用也一并弄丢。）

## 5. 两个必须写明的验收条件（否则结论会被读错）

### 5.1 验的是**当前 main 自建的二进制**，不是已发布的 0.2.3

已发布的 `Cante_0.2.3_x64-setup.exe` 指向 `292008d`，它**含** #173 的基础停滞处理（`3baaa4c`），
但**不含** #188 的后续（`16d030f`：`做完了 N 个操作`、停滞那块单独一屏、`再试一次 = 从头重做` 的语义）。
两条证据：

1. 源码层：`git show 292008d:gui/src/simple/copy.ts` 里**没有**「已经做到这里」那一块；
   `16d030f` 不在 `gui-v0.2.3` 的祖先里。
2. **真机层（更硬）**：本次 `cut` 的屏幕里**看得见**「做完了 2 个操作」——
   这句话只有 `16d030f` 之后才有。所以这三条结论对应的是 `1bc702e`。

### 5.2 应用先复制到**隔离目录**再跑（一个真实的工具链陷阱）

从工作树直接跑构建产物时，随包发的 `pi` 起不来：

```
error: Cannot find module '@earendil-works/chord/context'
       from '…\gui\src-tauri\target\debug\pi\dist\bundle\chunks\chunk-JVUZSMYM.js'
```

**真因**：`pi` 的 bundle 里 `@earendil-works/chord/context` 是外部依赖，靠 `node_modules` 解析；
而**从工作树跑时，产物的祖先目录里有 `gui/node_modules`**（`bun install` 装的），
bun 的解析会去那儿找、找不到就报错。把这个应用**复制到一个上面没有任何 `node_modules` 的目录**，
同一个 `pi` 立刻正常（`pi --version` → `0.85.1`）。

- 这是**开发工作树独有的坑**，**不是产品缺陷**：装好的 `%LOCALAPPDATA%\Cante` 没有这一层，不受影响。
  三种现场最初的两轮跑，因为这个原因应用根本收不到任何事件（屏幕一直停在「正在做这些事」）——
  那一度很像「产品在断网时什么都不说」，**差一点被当成产品结论**✗。所以验收脚本现在
  先复制到隔离目录，并把这个事实打在报告里。
- 顺带：`run-offline.ps1` 里我**自己**写错过一次路径深度（`Repo` 少了一层，找构建产物时拼成
  `gui\gui\…` 找不到，于是**静默回退到装好的那份**）—— 这意味着**前两轮验的其实是 0.2.3 安装包**。
  发现后已修正：现在报告里会打印「应用（原始）→ 应用（隔离副本）」，两者都能核对。

## 6. 我没能验证什么（如实列，不写成「通过」）

1. **真拔网线 / 真断 wifi** ✗ —— 这一轮造的是**等价现象**（端口没人听、socket 静默），
   不是物理断网。物理断网会额外影响 DNS、系统代理、以及 WebView2 自己 —— **没验**。
2. **真企业代理（Zscaler/Netskope 这类）** ✗ —— 我用的是一个**回 403 的本地中继**，
   模拟「网关挡住」这种**错法**，不是真的穿过公司代理栈。真实企业代理还会插入证书、
   返回带 HTML 的 403 页、或挂起连接 —— 这些**都没验**。
3. **每次现场只拿到一轮有效结果** ✗ —— 现场跑一次要 1~5 分钟，而 WebDriver 会话偶发中途死掉
   （`ECONNREFUSED … invalid session id`），有几次跑成了 `timeout-no-outcome`。这类空白是
   **工具链**的问题，**不算产品现象**（脚本会在结果里标 `sessionDied` 并在日志里明说）。
   有效结果的实际条数：**dead 4 次**（结论一致）、**cut 1 次**、**forbid 2 次**（结论一致）。
   要想更硬，应各跑 3 次；脚本已经能跑，只是这一次没跑那么多。
4. **有一次跑出来「假阴性」，我已经把它标掉** ✗（**很重要的一条**）：
   某一次 `dead` 跑出来是**成功**（「做好了」），而端口明明是死的。查下来是**现场没摆上** ——
   pi 没有用我们指的配置目录（它走了这台机器的真网关，所以当然不会报断）。
   为了不再把这种运行当成证据，脚本里加了一个**注入哨兵**：pi 真去用了那个配置目录时，
   它会自己在那里写 `auth.json` / `models-store.json`；跑完看不到这两个文件，脚本就打印
   「**现场注入了 = False**」并以**环境问题（退出码 2）**结束，而不是当成产品结论。
   事后回查：三次 `dead` 里那次可疑的**确实**没有哨兵，其余（死 4 次 / cut 1 次 / forbid 2 次）**都有**。
   > 教训：验收脚本必须**自带「现场真的摆上了吗」的核对**，否则一次假阴性就会把报告的结论带偏。
5. **`forbid` 的**「她做得到的动作」**这一条，我没法给通过** ✗ —— 因为它给的动作就是错的（§3.3）。
   这正是要报告的东西，不是要绕开的东西。
6. **没有在 GUI 上验证真实点击后的去向** ✗ —— 我验的是**那一屏说了什么**（文字/HTML/按钮都在），
   没有逐个点下去看「关掉那个窗口再试」按了之后会发生什么（那是另一个问题：
   一个指向不存在动作的按钮，点了会怎样）。
7. **企业预置那台机器没验** ✗ —— 结论只来自这一台验收机（`CANTE_ADMIN_CONFIG` 未设，
   `allow_network` 用的默认）。

## 7. 交付物（都在 `gui/scripts/windows/` 下）

| 文件 | 作用 |
| --- | --- |
| `run-offline.ps1` | 一条命令跑一种现场：隔离应用、清残留、摆假服务方、驱动窗口、落盘、核哈希 |
| `offline-probe/relay.mjs` | 假服务方：`dead` / `cut` / `forbid` 三种行为 |
| `offline-probe/drive-offline.mjs` | 在真 WebView2 里跑到**结局页**并把那一屏落盘（失败页也是有效结局） |
| `offline-probe/bridge-probe.mjs` | 绕过应用、直接按协议驱动 `cante-bridge`（用来**隔离**「现象来自产品还是工具链」） |
| `offline-probe/classify-assert.ts` | **判据脚本**：直接 import 产品的 `recovery.ts` / `copy.ts`，断言网络错误不被说成文件错误（§3.3） |

**建议的下一步（按任务边界我没有动 `src/**`）**：

1. 修 `BUSY` 里 `locked by` 那条：它不该匹配 "blocked by"。最省事的改法是把它收紧成
   词边界形式（例如只认 `file is locked by` / `locked for writing`），并在
   `recovery.test.ts` 补一条 **403 + "blocked by"** 的用例钉住它；
   同时**保留**真正的文件占用（`EBUSY` / `~$` / `openpyxl … locked`）那几条对照。
2. 考虑把 `classify-assert.ts` 的断言搬进 `gui/src/simple/recovery.test.ts`
   （那里才是 `bun test src` 会发现的地方）—— 现在它是个**独立脚本**，不会自动进闸门。
3. 企业代理那种 403 该给什么动作，是个**产品决定**（网络问题 → 「过一会儿再试」是现成的；
   要不要专门说「可能是公司的网络挡住了」见 `networkWhat` 已有的那句话）—— 留给产品拍板。
