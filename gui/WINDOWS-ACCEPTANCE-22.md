1. **读屏实际念出来的样子，抓到了** ✓ —— Narrator 真的念了我们应用里那些控件。

3. **念的不是我们列的那张清单**：我按 UIA 树算出来的"整行 100 字列表项"（§4 坑 1）

## 1. Narrator 在这台机器上的实况

### 1.1 在、且**能用 ETW 抓到它真正要念的句子**

```powershell
Get-WindowsCapability -Online -Name 'Narrator*'     # 报错：需要管理员（这条路走不通）
ls C:\Windows\System32\Narrator.exe                 # 在，10.0.26100.8972
```

关键的一步是**用 ETW 听 Narrator 自己**（它是**单例**、没有命令行、窗口里没有可操作节点，
所以"驱动它"这条常规路不通 —— **但它会把要念的句子通过 ETW 吐出来**）：

```powershell
# 提权后（logman 建 ETW 会话要提权）
logman create trace CanteNarrResults -p 'Microsoft-Windows-Narrator' -o results.etl -f bin -ets
#   …此时盲按 Tab 走一遍结果面板…
logman stop CanteNarrResults -ets
tracerpt results.etl -of XML -o results.xml -y
```

**实测**：ETW **3822 个事件**，XML 4.2MB，其中带 `SpokenText` 字段的 **168 条**
（相邻去重后 **76 条**）。字段名就是 `SpokenText` —— 那是 Narrator **交给语音引擎的那句话**。

> **为什么这比"驱动 Narrator"更值**：`SpokenText` **就是朗读的输入**。
> 它比"把 UIA 的 Name 抄下来再自己拼一句"可靠得多 —— 拼法（加不加"按钮"、
> 标题怎么念、列表怎么念）**由 Narrator 自己决定**，我们能看到真的那一句。

### 1.2 关于"驱动不了"要更正一句

我一开始试的路（`Narrator.exe /?`、启动它再看窗口）**都失败**，差点就写"驱动不了"：
- `/?` **没有任何输出**（不是个 CLI）；
- 启动它，进程**立刻退出**（`ExitCode=-1`）——**真因是单例**：机器上已经有一个在跑
  （pid 2452），再起一个当然立刻退；
- 它**杀不掉**（`Stop-Process -Force` 报"拒绝访问"）—— 受保护的系统进程。

**更正**：**"Narrator 在跑"这件事正是能抓 ETW 的前提**（它得在跑才会吐事件）。
所以结论不是"驱动不了"，而是：**不能给它下命令，但能听它说话** ✓。

### 1.3 为什么"真正出声"验不了：**没有声卡**

```
Win32_SoundDevice count = 0
Audiosrv             Running
AudioEndpointBuilder Running
```

服务在跑，但**一个音频端点都没有**。所以"她戴着耳机听到的声音"这一层**验不了**（§5）。
下面所有"念多久"是拿**系统中文语音**（`Microsoft Huihui Desktop`，zh-CN）把
**Narrator 要念的那串文字**合成 WAV、读 WAV 头算出来的 —— **不是**从音频设备抓的。

## 3. 三条最值得说的问题（都有原始输出）

### 3.1 「对照：旧版」这一条**没成立**（先说不成立的）

想给一个"#230 之前 / 之后"的**口头对照**：同一台机器、同一份夹具，拿**装好的 v0.2.3**
（#230 之前）抓一遍。结果那一轮 `SpokenText` 里**一句"打开…结果…"都没有**：

```
installed.xml：SpokenText 总数 = 89
  含「打开」的 = 0 条
  含「结果」的 = 0 条
  含「回到首页/搜索做过的」 = 0 条
```

**为什么**：那一轮**焦点没走到结果行的按钮上**（探针里应用启动后的会话/焦点时序与新版那一轮不同，
Tab 没落到面板里）。所以**这一条只能写"没抓到"** ✗ ——
**不能**据此说"旧版念不出来"。**要真做这个对照，得让旧版那次也确定走到按钮上**
（拿 Narrator 的 `ElementAddress` 对着断言），本轮**没做到**。

### 3.2 真正被念出来、但**不该念**的三样（环境的噪音）

从 `results.xml` 的 168 条 `SpokenText` 里数出来的：

| 念的东西 | 次数 | 原文 | 为什么不该念 |
| --- | --- | --- | --- |
| **「扫描」** | **36** | `「扫描」` | 这是 Narrator 的**屏幕扫描**状态词，**不是** Cante 的界面。它在面板上反复出现，把朗读切得七零八落 |
| **输入法状态** | 6 + 3 + 11 | `「英语输入模式」`/`「中文输入模式」`/`「输入 英语, 我做的结果 对话框, 打开 … 按钮,」` | 输入法**不是**应用内容；而且它**插进了一句本来完整的话中间**（§2.2 那三行就是） |
| **窗口标题当名字** | 9 + 3 | `「C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe, 正在编辑,」`、`「Cante 窗口,」` | 把**可执行文件全路径**当"正在编辑"的名字念出来 —— 这是 PowerShell 窗口（我这一轮的工具），说明"前台窗口切换"会**整个插进朗读** |

**为什么值得说**：这三样**都不是 Cante 能控制的**（是 Narrator + 系统窗口 + 输入法），
但它们**会挤进她听到的流**。报告如实列出来，**不把它们算成产品缺陷**。

### 3.3 最刺耳的 3 条（按"念出来最不像人话/最长"）

> 秒数 = 把 **Narrator 要念的那串文字**（`SpokenText`，去掉 SSML 标记）交给本机中文语音合成的时长。

| # | 句子（**逐字取自 ETW**） | 字数 | 念出来 | 为什么刺耳 |
| --- | --- | --- | --- | --- |
| **①** | `把几张表合成一张（自动去掉重复行）。把这三个月的销售表合成一张，重复的记录只留一条` | 41 | **10.7 秒** | 这是**一张卡片的可访问名字**。它把「卡名」和「例子」用**句号**连成一句 —— 读屏把**一张卡念 10.7 秒**，而她要在一屏 33 张卡里选。30 多张卡全这样，光是听卡片就要**几分钟** |
| **②** | `打开 结果_挑出华东区-1.xlsx` | 18 | **5.5 秒** | 每个结果行**两个按钮各念 5.5 / 6.8 秒**。同一份文件的名字她要**听两遍**（"打开 X" 和 "打开 X 所在的文件夹"）；对照：同样意思的纯中文 `打开第一份华东区的表格文件`（13 字）只念 **3.6 秒** —— 差在**下划线、连字符、`.xlsx` 被逐字念**（§3.3 表下注） |
| **③** | `退出列表, 标题级别 2 我做的结果 你做过的东西都在这里，最近的在最上面。` | 38 | **8.1 秒** | 一句里**混了三种东西**：一个操作词（"退出列表"）、一个**技术词**（"标题级别 2"）、然后是标题+副标题正文。读屏用户听到的是**一串没有停顿的东西**，而"标题级别 2"这种词**对她没有意义** |

**② 的补充**（用同一语音量的片段）：

```
"_"                  念 1.7 秒   ← 一个下划线比 5 个中文字（挑出华东区，2.2 秒）还慢
".xlsx"              念 2.3 秒
"-1"                 念 1.4 秒
"结果 挑出华东区 1"   念 2.9 秒   ← 下划线换空格，同样内容快很多
```

## 4. 踩过的坑（都是「看起来像产品坏了、其实是工具/环境」）

1. **我算的"念法"高估了**：按 UIA 树算，会得出"结果面板每行那个 100 字的 `ListItem`
   会被念 **25.6 秒**"。**Narrator 实际一次都没念它** —— `ListItem` **不可 Tab**
   （`focusable=False`），键盘走不到，读屏也就不念。**教训**：读屏念什么**取决于它怎么走**，
   不是"树里有什么"。**这一轮的 ETW 就是来纠这个的。**
2. **路径少算一层 → 静默验了旧应用**：脚本在 `windows\a11y\`（比 `a11y-uia.ps1` 多一层），
   第一版 `..\..` 算成 `gui\scripts`，找不到现构建就**回退到装好的那份** ——
   于是看到的是**修复前**的按钮名，差一点写成"#230 没生效"✗。
   **修法**：改 `..\..\..`，并**每次都把实际用的 exe 路径打在输出里**（靠它发现的）。
3. **Narrator "起不来"是假象（单例）**：再起一个立刻 `ExitCode=-1`，看着像崩溃；
   真因是**已经有一个在跑**。**修法**：先 `Get-Process Narrator` 看有没有，有就复用它。
4. **`«开始使用»` 在折叠之下 → UIA 不支持 `Invoke`**：报"不支持的模式"。
   先 `SetFocus` + `ScrollIntoView`（必要时真滚轮）再点。
5. **向导第二步的按钮不固定**：「下一步」或「先看看界面」二选一，写死顺序会卡住 → 循环点。
6. **`if` 不能当表达式拼字符串**（PowerShell 5.1）：先算进变量再拼。
7. **从窗口根遍历 → 混进 Edge 自己的 chrome**（最小化/关闭/翻译/收藏）→
   改成**从应用的 `Document` 元素**开始走。

## 5. 我没能验证什么（如实列，不写成「通过」）

1. **"真正出声、她听到的声音"没验** ✗ —— **这台机器 `Win32_SoundDevice` 数量 = 0**
   （没有音频端点）。我验的是 Narrator **要念的那串文字**（ETW 的 `SpokenText`），
   **不是**从音频设备抓到的声音。**所以**：语速、停顿、重音、念错字、以及"声卡/驱动
   会不会把中文念成乱码"这一层**一条都没验**。
2. **"#230 之前"的口头对照没成立** ✗ —— 旧版那一轮焦点没走到结果行按钮上，
   `SpokenText` 里没有"打开…"的句子（§3.1）。**只能说"没抓到"，不能说"旧版念不出来"。**
3. **"两份结果之间能不能跳"只验到"没有落在结果上的标题"** ✗ ——
   面板里有 `标题级别 2`（面板自己的标题），但**6 行结果上都没有标题**，
   所以**按标题跳**不行。读屏还有别的跳法（"下一个列表项""下一个按钮"），
   我**没有**逐种验过它们好不好用。
4. **`ListItem` 不可 Tab 这件事的产品含义没定论** ✗ —— 读屏**不念**行内那些文字
   （时间、状态），所以她**听不到**"这次没能核对它还在不在"。这是**好事还是坏事**
   （信息少 vs 不啰嗦）是**产品决定**，本轮只报事实。
5. **只跑了少量轮次** ✗ —— `results` 的 ETW 抓了 3 次（2 次成功、1 次旧版没抓到），
   `home` 1 次。没有做到"各 3 次一致"。
6. **只有 WebView2 这一种宿主** ✗ —— 换宿主（macOS WKWebView 或将来换运行时）UIA/Narrator
   的行为可能不同，**没验**。
