# Cante 桌面版 · 产品路线图

> 面向**中国的非 IT 办公室用户**。不是开发者工具。

## 1. 目标用户

**王姐，45 岁，行政/财务。** Windows 笔记本，微信 PC 版常开，Excel 只会复制粘贴和求和，
文件散落在桌面、下载文件夹和微信的接收目录里。她**不认识**这些词：模型、provider、token、
prompt、会话、上下文、权限模式、工具调用、diff、worktree、路径。

### 三条产品律（所有取舍以它们为准）

1. **她买的不是"能力"，是"这件事帮我做完"。** → 入口是任务，不是空白输入框；文案全中文、零术语。
2. **她放弃产品的原因是"怕弄坏东西"，不是"功能不够"。** → 先证明安全：永不覆盖原文件、可撤销、重要动作先说清楚。
3. **她出错时无法自救。** → 错误必须是「发生了什么 + 你可以怎么做 + 复制详情给技术同事」。

## 2. 差异化：做 WPS 做不到的「跨应用整件事」

竞品事实：WPS AI 已原生覆盖**单文档内**的表格能力——自然语言公式、数据清洗与补全、一键透视+图表、
**图片转 Excel OCR**、PDF 对话。**单文件 Excel 技巧是入场券，不是护城河。**

我们只在 WPS 够不到的地方建立价值：

| 维度 | WPS | Cante |
|---|---|---|
| 跨文件 | 单文档模型 | 5 张门店表合成一张并对账、去重、差异比对 |
| 跨应用 | 碰不到 | **微信**里收到的表/接龙/文件（中国办公室真正的数据入口） |
| 跨时间 | 无 | 每周一自动整理上周销售表 |
| 跨格式 | 文档内 | 文件夹整理、PDF 批量处理、跨格式转换 |
| 形态 | 在 Office 里帮你写 | **在 Office 外面把整件事做完**，然后告诉你结果在哪 |

产品话术只讲后者。**不声称"替代 Office"，不比函数与样式。**

## 3. 信任架构（有实证依据）

依据：Wharton《AI Agent Adoption Blueprint》(2026) 的对照实验。

| 实证结论 | 我们的实现 |
|---|---|
| **解释过程**显著提升"可靠、安全"评分 | 确认页给出确定性 plan；执行中逐条显示进度（#62） |
| **承认已知局限**反而提升信任 | 每个任务在确认页列出"可能不准的情况"，结果页标出本次实际触发的风险（#63） |
| **真实成功证据**比技术解释有效（信心 +22%） | 显示本机真实统计："这个任务你做过 7 次，都成功了"（#64） |
| 用户要**共同决策**，不要全自动也不要事事请示 | 破坏性动作强制确认（#42）；其余动作先给 plan 再执行；定时任务默认"先问我"（#55） |
| **能力感 > 亲切感**：引用依据、平实陈述 | 文案基调：平实 + 有依据，不卖萌（#66） |

安全底座（无条件的）：**结果永不覆盖原文件**（#41）、**一键撤销**（#43）、**操作日志**（#57）。

## 4. 优先级（RICE 排序，触及人数 × 影响 × 确定性 ÷ 成本）

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 任务卡片首页、首次运行向导、永不覆盖原文件、预览确认、一键撤销、大白话错误、隐私面板、多表合并去重、审批大白话、步骤可见、局限披露 | 没有这些，她**不敢用**或**用不起来**；其中多表合并是第一个"哇"的瞬间 |
| **P1** | 微信整理（只读）、微信草稿（人工发送）、文件批量整理、PDF 批处理、分组统计+图表、格式整理与差异、执行步骤可见、局限披露、成功证据 | 差异化最大的是微信与文件批处理；信任三件套有实证支撑（见 §3） |
| **P2** | 截图转表格（**通道阻塞**）、资料整理、定时任务、语音输入、历史搜索、企业统一配置 | 价值真实但依赖前面稳定；截图转表格要等图片通道（见下） |

## 5. 里程碑

**王姐的 MVP**（GitHub milestone「王姐的 MVP：非 IT 用户可用」）：
一个不懂电脑的办公室用户，在**没有任何人帮助**下完成三件事——合并多张表、整理一个文件夹、写一份通知——
全程不需要理解任何技术词，且敢在真实工作文件上使用（因为不会被改坏、能撤销）。

## 6. 决策日志

| 日期 | 决定 | 依据 |
|---|---|---|
| 2026-09 | **产品只保留一个界面**，删除面向开发者的"专业模式"（多会话/worktree、diff review、CI 监控、命令面板、终端抽屉、token 读数） | 目标用户不需要第二套界面；维护两套会长期分散精力，且技术术语与画像直接冲突 |
| 2026-09 | **微信只做整理与草稿，永不自动发送/群发** | 封号风险 + 公司合规；把"写"与"发"分开既省力又不越线 |
| 2026-09 | **附件 = 被引用的路径** | 协议只承载文本（`UserInput(String)`）；不能上传图片字节，就不假装能 |
| 2026-09 | **撤销不依赖 agent 配合** | Rust 侧对目录做前后快照 diff 得出"新增了哪些文件"，据此撤销；把安全建立在可验证的事实上，而不是模型的承诺 |
| 2026-09 | **Plan 模式改为客户端行为**（追加系统提示 + 禁用编辑工具） | cante 的权限枚举只有 Strict/Auto/Yolo，没有 Plan；不因此卡住用户 |
| 2026-09 | 简单模式默认用「自动」权限，危险动作仍会问（用大白话问） | 每步都问会打断非 IT 用户；完全放开又不安全（#60） |
| 2026-09 | **截图/照片转表格暂缓（P1 → P2）** | 协议只承载文本（`UserInput(String)`），视觉模型也用不上；本机又普遍没有 OCR 工具。**不做会让用户白等的功能**；可行路径是上游加附件通道，或我们在 Rust 侧内置纯本地 OCR（#48） |
| 2026-09 | 执行步骤、局限披露、成功证据提到 P1 最前 | Wharton 2026 的对照实验：解释过程、承认局限、展示真实成功证据，三者都显著提升信任，且比"亲切"有效 |
| 2026-09-16 | 做"能力中心"（按"你想做什么"搜索的精选目录），**不做开放插件市场** | 王姐无法判断第三方能力是否安全，要求她判断＝用她的文件替我们试错；她的真实问题不是"能力不够多"而是"不知道它能干什么"（#74） |
| 2026-09-16 | 缺失读写格式的能力（如 .xlsx）时，**先在第一屏说清并给替代方案**，不许硬做、不许假装成功 | 真机跑 #45 时助手到最后一步才发现本机没有写 xlsx 的工具；"白等然后失败"比"提前说做不到"更伤信任（#75） |
| 2026-09-16 | **评估过 WPS 加载项渠道，不做**：WPS 开放平台确实提供完整的加载项开发与分发（"生成首个 WPS 加载项"有官方文档），且有社区在讲怎么分发 | 加载项天然被关在**单个文档、单个应用**里，而我们的差异化恰恰是"跨应用整件事"（跨文件、跨应用、跨时间）。搬进去等于放弃战场，还要接受商店审核与宿主版本兼容；反过来说，**如果哪天我们想做单文档的表格技巧，说明我们已经输给了 WPS**——那才是该重新考虑这个渠道的信号 |
| 2026-09-16 | 助手"先问我一句"必须配**能回答的入口**，否则等于没有这个承诺 | 真机（本地模型与网关模型各一次）都在列名不一致处停下来问，而结果卡片当时没有任何输入框，旗舰任务走到死路 |
| 2026-09-16 | **把 store 里为已删界面留下的机制真正删掉**：命令面板与 slash 命令（含 commands.ts）、模型/强度/权限选择、视图密度、能力清单、目标条、终端抽屉、catalog、cwd/mode、ambient/steer，以及只被旧界面读的分支。`rows` 行流**保留**——结果卡片的 #63「需要你核对」与 r7「是否在提问」仍从最后一条助手行读取。store 现在只剩三件事：把事件折成行与运行记录、把她的操作翻成契约命令（选文件/确认/撤销/定时）、以及桥接生命周期。 | 界面只剩简单模式后这些成员没有任何生产代码读到，只被测试覆盖；留着会让下一个人以为它们还在服务某个界面。只按"外部引用"审计会得出"一个都不能删"的错误结论，必须顺着 store 内部的调用链看 |

## 6.5 场景清单（2026-09 联网调研驱动）

用 agent-reach 对中文办公人群做了一轮调研（B站高播放教程、金数据/金蝶/畅捷通/影刀等厂商内容、微软与火山引擎的企业 AI 安全文、财务与行政社区的实操贴）。**结论：凡是"每月重复、跨文件、跨应用"的活，都有人在用 Excel 硬凑，也都有厂商在卖工具——说明这是真需求，不是我们臆想。**

| 场景 | 她现在的做法 | 我们有吗 | 结论 |
| --- | --- | --- | --- |
| 微信群接龙/报名 → 跟进表（去重、统计份数、找没交的） | 人肉数、复制粘贴 | 部分（#51/#52 只读与草稿） | **补专门卡片**（#86）：这是调研里最具体、最被反复解决的一个动作 |
| 电子发票 PDF → 台账、发票查重 | 手工敲；或用"发票转 Excel"类工具 | 工具已具备（#75/#81 的 `cante-pdf` + `cante-sheets`），**卡片没有** | **马上能做**（#83），且不联网、不上传 |
| 月末对账、表内合计核对 | 手工核对，怕漏 | 只有"两表差异"一张卡（#47） | **补"帮我检查"这一类**（#84）：核对比生成更值钱——生成错了她挨骂，检查出来她能改 |
| 考勤汇总、花名册合并、合同/证照到期提醒 | 多张表手工拼，用 Excel 硬凑提醒 | 合并的底子在（#45），缺"按人对齐"与"找变化" | **补行政月度例事族**（#85），并能配合定时任务（#55） |
| 上级/外部模板的上报汇总 | 按模板重排、逐格核对 | 部分（合并保持列序一致） | 观察：模板本身是外部约束，先做好"按列名对齐 + 保持表头顺序" |
| 扫描件/照片里的表格 | 手工敲 | 做不到（#48：协议只承载文本、本机无 OCR） | **维持不做**，但要"说清楚做不到"（已有中性提示） |
| 资产/库存盘点核对 | 打表、逐项对 | 核对族（#84）可覆盖大部分 | 归入 #84，不单独立项 |
| 报销单据与发票台账核对 | 手工翻 | 核对族（#84） | 归入 #84 |
| 材料/纪要/通知起草 | 找模板、改措辞 | 有（#53） | 保持 |
| 查政策/资料并整理成文档 | 到处搜、复制 | 有卡（#54），未真机验收 | 排后 |
| **不敢用**：怕数据外传、公司不许装 | 宁可用 Excel 硬扛 | 隐私面板（#40）+ 本地模型 + 只在本机处理 | **这是最强的差异点**：厂商文章标题就是"80% 员工偷偷绕开公司 AI 工具"、"数据泄露与权限风险"——我们要把"不联网也能干"讲清楚（#58 企业预置） |
| 月度总结 / 周报 / 述职（"怎么写日常琐事才不显得碎"是真实搜索） | 找范文、硬凑 | 有（#53 文书族） | 保持；可考虑加一张"个人工作总结"变体 |
| "**先给我看一眼再交上去**" | 反复检查、怕担责 | 有（先试跑 + 动手前确认） | 这是信任设计的落地形态，要在界面上更显眼，而不是藏在按钮里 |
| 语音说需求 | 打字 | 没做（#56） | 维持不做：系统自带听写已经够用，自研收益低 |

**从这张表读出的产品走势**：我们的差异化不在"更聪明的 Excel 助手"，而在**跨应用、跨文件、每月重复、且数据不出本机**。凡是需要"新系统/新账号/上传数据"的方案，对这个人群都是高墙——而这正是我们的入口。

## 6.7 真机普查（2026-09）

`gui/scripts/task-sweep.sh` 把"真机验收"做成了可重复的事：为每张卡造脏输入、用**产品真实的指令**（`instructionFor`）驱动真实守护进程、自动应答审批、收集产出并核验，最后生成 `gui/scripts/sweep/report.md`。

第一次跑完 **26 张卡**：**19 通过 / 6 停下问问题 / 1 超时**。它当场挖出三件事，都已修：

1. **助手会用英文回话**（微信整理卡的最后一句是英文）→ 公共规则里加了「【说中文】」；
2. **单卡超时太短会把成功误判成失败**（慢模型实测 850 秒，默认只给了 600 秒）→ 默认改成 1800 秒，可用 `--timeout` / `SWEEP_TIMEOUT` 覆盖；
3. 「停下问问题」一度被记成失败——那其实是**符合设计的结果**（提示词要求它在拿不准时先问），普查的判定里现在单独一类。

**它同时暴露了方法论问题**：普查最初调用 `task.prompt()`，而生产路径是 `instructionFor()`——也就是"测了一条产品不会走的路"。这正是 #93 那个 P0（卡片提示词从未发出）能潜伏那么久的原因。现在两者都走 `instructionFor`。

## 6.8 新功能的诚实边界（2026-09）

- **看图（#48）**：卡片、能力探测、中性回退都做好了，真机也验证了**回退路径**（模型没有视觉时，助手如实停下并给出两条出路）。看图路径**只在图片真的被送到模型时才成立**——本机只有本地 mlx-serve 的一个视觉模型真的收到了图（它正确认出被遮挡的格子并留空、在「需要你核对」里点出来）；网关上一批多模态候选要么收到 `[image omitted]`、要么明说看不了、要么直接编内容。**这个"图片有没有随请求送出去"取决于宿主 `ante` 二进制，不在本仓库**。所以这张卡暂不承诺"一定能看图"，界面上以模型的视觉标记决定是否标注"做不到"。
- **查资料（#54）**：真机验证通过（出处真实、独立核对过、写明查询时间、查不到的单独列出、没有编造）。两个前提要写清：**能搜**依赖本机有可用的检索途径（内置检索没被用上，助手用了本机的 exa/mcporter 技能）；**转 Word** 在本机走的是 macOS 的 `textutil`，**Windows 上大概率只能产出 .md/纯文本**——卡片的风险披露里已经写明会如实告知格式，不假装转好了。
- **结果核对**：能核对"文件在不在、多大、能不能打开"，**不能**核对内容对不对（数字算错、漏行、格式乱都看不出来），也不能判断它是不是"你要的那一份"。这条边界写在报告与代码注释里，不夸大。
- **排队（#55 之外的新能力）**：只负责"排好、逐个领到确认页"，**不做全部自动执行、不做跨重启恢复**——前者与"动手前先问人"冲突，后者会在她已在别处做完时恢复错东西。

## 7. 明确不做

- 不做 Office 替代品 / 编辑器 / 公式编辑器
- 不做面向开发者的界面与术语
- 不做无人值守的破坏性操作；定时任务遇到破坏性动作必须停下问人
- 不做云同步、账号体系、在线支付
- 不做自动加好友 / 群发 / 朋友圈发布
- 不编造成功率、不写无信息量的免责声明
- 不做第三方能力的上传、分成、安装与评分：评估一个插件是否安全的责任不能推给非 IT 用户（#74）
- 不做"先跑起来再报错"：本机缺工具（读不了/写不了某种格式）必须在**动手前**说清并给出替代方案（#75）
- 不把"专业模式"的机制加回 store：命令面板 / slash 命令、模型与强度选择、视图密度、能力清单、目标条、终端抽屉、catalog。界面只有一个，没有消费者的状态就是负债；`rows` 行流是唯一的例外，因为它还喂着结果卡片的信任文案
