## 5. 一个必须写明的环境事实：两个验收在哪台机器上会互踩

这一轮我**第一次跑失败**了 —— 应用跑到结果页前一步**进程突然消失**（pid 10016，UIA 树失效）。
查进程表发现：**同一台机器上另一个工作树（`<另一个工作树>`）正在跑它自己的 GUI 验收**，
用的是**同一个装好的应用**、**同一个进程名**、**同一份 `%LOCALAPPDATA%\dev.cante.gui`**。

真因不是偶发：`run-accept-drive.ps1` 开跑前会
`Get-Process cante-gui | Stop-Process`（清残留，否则新会话抢不到调试端口），
**两个并行验收会互相把对方的应用干掉**。这条其实已经写在脚本自己的注释里
（`$Port` 那条参数，第 64 行：「两台并行的验收都去杀 cante-gui / 抢同一个端口，会互相把对方的应用干掉（实测）」）。

**这一轮怎么绕开的**（两条都不改产品、也不改仓库脚本）：

1. 用 `read-result-page.ps1`（**UIA 自己启动应用**，不经过 WebDriver / 不占 4444 端口）；
2. 把应用复制到一个**隔离目录**并**改个文件名**（`cante-gui-vm.exe`）—— 对方那句
   `Get-Process cante-gui | Stop-Process` 就抓不到它。**二进制逐字节相同**（sha256
   `C91B5CCD…`，与构建产物一致），所以验的还是同一份东西。

**这是一条流程约束，不是产品问题**：同机并行跑 GUI 验收要么**串行**，要么各自改名 + 各自端口。
我另外给隔壁 agent 发了消息说明互踩；`§0` 那条默认一行命令能跑通，是在对方没杀我应用的窗口里跑成的。
